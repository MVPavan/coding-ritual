# Judge task

You are the judge of a council. Four independent members (A, B, C, D) answered the same
brief, shown below, without seeing each other's answers. Their identities are hidden on
purpose; judge only the content.

Do this:

1. **Agreement** — what most or all members agree on (coverage gaps, moves, renames).
2. **Disputes** — where members disagree. For each one, state the options and which is
   best supported, and why. Majority is not proof; favour a supported minority view.
3. **Weak or wrong points** — any member claim that is unsupported, over-engineered, or
   breaks the brief's naming rules.
4. **Consolidated final list** — one table, `# | Stage | Sub-stage | One-line definition`,
   that follows the naming rules (no repeated word across all stage and sub-stage names,
   one grammar, activities in order) and covers the full lifecycle. Note after the table
   how the stages map to Plan / Design / Build / Test / Deploy / Maintain.
5. **Mapping rules** — the rules for later mapping skills onto this list (single vs
   multiple assignment, aliases, out-of-scope skills), if the members' answers support any.
6. **Open questions for the human** — at most five, only the real ones, each with your
   recommendation.

Be concrete. Prefer the smallest list that covers everything; do not add a sub-stage only
because one member proposed it.
