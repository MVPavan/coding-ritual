00Summary

  • pstack is a Cursor plugin. One sticky router skill (poteto-mode) matches 23 playbooks and draws on 24 principle skills. It assumes GitHub PR stacks with CI, Cursor cloud agents, the /loop wake command and three model families. Its described setup also feeds Bugbot and a security-review bot into PR triage, but the data file judges those bots inputs, not requirements, for the autonomy path (pstack.md:440). It enforces nothing in code: every stop rule is prose. Its only deterministic parts are watch-pr, orch, check-plan and worktree-audit (pstack.md:441).
  • Matt Pocock's skills are human-orchestrated. A skill may never call a user-invoked skill, so a human types each step of the main flow (grill, spec, tickets, implement, retro). The most it runs alone is one implement-spec session, and only if the test seams were agreed beforehand. It leaves truly unattended (AFK) work to an outside loop (pocock.md:39, 278).
  • Ours has two layers. The prose harness (skills, agents, hooks, Beads) drives a deterministic Python engine: foreman, contractor, inspector, crews, run ledger. There is no CI and no PR flow. Landing is a local compare-and-swap behind a signed human ship gate (ours.md:8-11, 17-18).
  • Headline difference. pstack hands its gates to GitHub, CI, bots and an independent live verifier, and it enforces by prose. Ours enforces in code (host verify, bwrap sandbox, signed gates, SQLite ledger) but lands locally. J: across the 22 problems, ours vs pstack is an alternative in 10, a complement in 11, and ours-only in 1 (domain glossary and ADRs).
  • Autonomy finding. In autopilot-full, pstack merges when it holds both the operator's grant and a clean verdict from an agent that did not write the code; in autopilot-stack the operator lands. /loop wakes it. Ours stops at three points (ours.md §6): a human-signed ship gate on every stage, a monitor hook_argv re-wake that is not wired up, and approval gates in the prose layer. J: section 6 gives a step for each. The ship-gate one is not a small step: it changes the trust model and needs the owner's explicit decision.

Our three known blockers (ours.md §6)

  • ship gate Every stage reaches shipped only through a signed human ship gate, and the approval is bound to the exact candidate commit. So /run-phases is not end-to-end unattended on the contractor path (ours.md:316-320; docs/specs/workflow-interpreter.md:1058-1095). Removing this stop is a trust-model change for the owner to decide, not a configuration step. J: the protection stops the foreman and crews from forging an approval. It does not technically stop an interactive orchestrator that has host key access; that boundary is policy (ours.md:321).
  • re-wake The monitor is a separately run process that can emit wake events, but hook_argv is commented out and nothing in the repo ships a receiver for it. Expected stops at a gate, terminal or wall limit use no wake slot (ours.md:306-311; docs/usage/engine-bundle.md:159-206).
  • prose gates Spec approval, plan approval before Beads writes, scope and safety changes, commit and push, accepting material risk, and merge abort all stop for a human (ours.md:324-330).

Caveats: pstack's own inconsistencies

  • Orchestrate needs Graphite gt (orch frontier execs gt info), while every other playbook says never to require it (pstack.md:14-15, 442).
  • "opening-a-pr at the end of every playbook" conflicts with the read-only playbooks: investigation, forensics, prototype (pstack.md:11, 442).
  • The README calls Comment Sicko read-only, yet it deletes comments (pstack.md:48, 442).
  • benny opens draft PRs despite the "never draft" rule (pstack.md:17, 442).
  • Audit ticks hard-code origin/main:pstack/..., which fails when pstack is installed as a plugin (pstack.md:33, 442).
  • The Autonomy section allows team-chat posts without asking, while p:never-block-on-the-human lists external messages as needing confirmation (pstack.md:36, 442).
  • J (pstack.md:441): pstack enforces nothing in code. To copy its autonomy you need its prose discipline, or our engine taking the place of that discipline.
