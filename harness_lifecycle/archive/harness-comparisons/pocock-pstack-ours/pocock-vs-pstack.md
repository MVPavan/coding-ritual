# mattpocock/skills (A) vs pstack (B): comparison

Scope: A = `reference_harnesses/mattpocock_skills` at 24fe0ef (v1.3.1). B = `reference_harnesses/cursor_plugins/pstack` (plugin.json v0.15.9).
Paths below are relative to `reference_harnesses/`. "Judgement:" marks my opinion. Everything else is read from the files.

## 1. What changed in A from v1.2.3 (84fdeff) to v1.3.1 (24fe0ef)

The diff is 114 files, +1780/-1190. Most of it is cosmetic: em-dashes were removed repo-wide (`mattpocock_skills/CHANGELOG.md` 1.3.0 patch #905), and the edits to existing SKILL.md files are mostly punctuation rewrites. I normalised away punctuation and the CONTEXT/GLOSSARY rename and found these material changes:

- **Added `implement-spec`** (`mattpocock_skills/skills/engineering/implement-spec/SKILL.md`). It runs a spec's tickets as a task graph. Implementer subagents each work in their own worktree across the ready frontier (lines 13, 27-34), a merger subagent lands each branch on one integration branch (l.32), and one `code-review` runs at the end (l.36). It is user-invoked.
- **Added `pr`** (`mattpocock_skills/skills/engineering/pr/SKILL.md`). It is a model-invoked template for PR bodies with three sections: Summary (the smallest visual that makes the change clear: pseudocode, call tree, or file tree), Evidence (before and after), and Merge Danger (one-way or two-way door, plus blast radius) (l.12-33). It is adapted from Humanlayer's `show-me` (`pr/CREDITS.md`).
- **Added `retro`** (`mattpocock_skills/skills/engineering/retro/SKILL.md`). It mines a session for changes to the agent's environment, not to the code. Its categories are navigation, automated checks, coding standards, AGENTS.md, tool economy, no-ops, and information access (l.57-63). Mechanical violations become deterministic checks, and `CODING_STANDARDS.md` is reserved for judgement calls (l.59). Reviewers, not implementers, enforce standards (l.71-75).
- **Removed `resolving-merge-conflicts`**, with no replacement (`CHANGELOG.md` 1.3.0, daa01d8; diff status `D skills/engineering/resolving-merge-conflicts/SKILL.md`).
- **Renamed `CONTEXT.md`/`CONTEXT-MAP.md` to `GLOSSARY.md`/`GLOSSARY-MAP.md`** across 11 skills. This is breaking for existing users, who must `git mv` their files (`CHANGELOG.md` 1.3.0, 006a52b). `domain-modeling/CONTEXT-FORMAT.md` became `GLOSSARY-FORMAT.md`, and the root `CONTEXT.md` became `GLOSSARY.md`.
- **Skills now call each other through the Skill tool explicitly**: "Call the Skill tool with "grilling"" replaces bare `/grilling` prose. A step that needs two skills is written as two calls (`.agents/invocation.md` "Dependencies between them"; `productivity/grill-me/SKILL.md`; `engineering/triage/SKILL.md` step 4; `engineering/wayfinder/SKILL.md`). The stated reason is that bare prose mentions did not reliably load the skill (`CHANGELOG.md` #878).
- **User-invoked skills are now never called from another skill.** Preconditions now say "tell the user to run `/setup-matt-pocock-skills`" instead of calling it (`to-spec`, `wayfinder`, `to-tickets`, `triage`, `code-review`). `.agents/invocation.md` gained a carve-out paragraph saying so (`CHANGELOG.md` #880).
- **`diagnosing-bugs` Phase 6 is now "Cleanup" only.** The post-mortem hand-off to `improve-codebase-architecture` was removed (`engineering/diagnosing-bugs/SKILL.md:130`; `CHANGELOG.md` #880). In its place, `ask-matt` routes to `/retro` after the fix (`CHANGELOG.md` 1.3.1).
- **`ask-matt` routing changed**: it now offers `/implement` per ticket or `/implement-spec` for the whole spec, `/pr` for the PR body, and `/retro` as main-flow step 4. It also says to run retro before `/clear` (`engineering/ask-matt/SKILL.md:36` and the step 3-4 block).
- **Small fixes**: the `grilling` round template now separates questions with `---` (`productivity/grilling/SKILL.md:17`). `wait-what` follows `GLOSSARY-MAP.md` (`productivity/wait-what/SKILL.md:7`). Six skills had their `description` YAML quoted because they were failing discovery (`CHANGELOG.md` #911).

## 2. Shape of each

**A (Pocock).** There are 37 SKILL.md files (2,631 lines) in buckets `engineering/`, `productivity/`, `misc/`, `in-progress/`, and `deprecated/`. Only the 30 promoted skills ship in the Claude Code plugin (`mattpocock_skills/AGENTS.md`). The one design axis is invocation. User-invoked skills (`disable-model-invocation: true` plus the Codex `policy.allow_implicit_invocation: false`) orchestrate. Model-invoked skills hold reusable discipline. A user-invoked skill may never call another user-invoked skill (`.agents/invocation.md`; README "Reference"). The entry point is the `ask-matt` router (`engineering/ask-matt/SKILL.md`) over a main flow: grill-with-docs, then to-spec, then to-tickets, then implement/implement-spec, then code-review, then retro. A per-repo `setup-matt-pocock-skills` configures the issue tracker, labels, and doc layout. There are no named agents. Subagents are generic and harness-neutral, with tool names stripped (`CHANGELOG.md` 1.2.3 #781). There is no multi-model use. Its philosophy is "small, easy to adapt, composable... work with any model" and it is anti-process-framework (`mattpocock_skills/README.md` intro, which names GSD/BMAD/Spec-Kit). It is centred on alignment through grilling, a shared domain language (GLOSSARY plus ADRs), TDD, and deep modules (Ousterhout).

**B (pstack).** There are 50 SKILL.md files (2,247 lines) plus 23 playbooks (622 lines) under `skills/poteto-mode/playbooks/`. There are two agents (`agents/poteto-agent.md`, `agents/comment-sicko.md`), a dormant Slack-triage automation pack (`automations/benny/`), a 10-chapter guide (`docs/guide/`), and TypeScript tooling (`poteto-mode/scripts/orch`, `watch-pr`, `check-plan.mjs`). Every skill except `setup-pstack` is `disable-model-invocation: true`. Routing goes through one sticky "mode" skill, `poteto-mode` (`mode: true`, with a `reminder:` frontmatter, `skills/poteto-mode/SKILL.md:1-9`). That skill matches a playbook, copies its steps verbatim into a todo list (l.121), and names triggers that pull in other skills (l.17-36). There are 24 one-rule `principle-*` skills, indexed inline in poteto-mode (l.38-79). Agents must cite a principle that shaped a decision, and may cite only principles whose leaf file they read (l.15). Multi-model use is core. A per-role model rule `~/.cursor/rules/pstack-models.mdc` written by `setup-pstack` (l.39-66) assigns grok to code, opus to judgment and prose, and an opus/sol/grok panel to arena, interrogate, and architect. Its philosophy is "if you want to go fast, go deep first", with "fearless parallelism", autonomy by default, and no planning skills ("the best spec is code") (`pstack/README.md:5-11, 243-245`).

## 5. Strongest ideas (borrowable)

Judgement: these are my picks. The evidence cited is fact.

1. **Fix a mistake class at the highest level that works, and keep a table pairing each rule with its enforcer.** The order is architecture, types, lint, test, docs. Prove each new check fails on a real past mistake. A correction to a rule that is already written down but unenforced counts as a repeat (`pstack/skills/correct/SKILL.md:19-30`; same idea at `principle-encode-lessons-in-structure/SKILL.md:19`; A's `retro/SKILL.md:59`). Why: it turns repeated corrections into checks that fail when broken, instead of instructions that grow.
2. **A tight, red-capable feedback loop before any hypothesis** (`mattpocock_skills/skills/engineering/diagnosing-bugs/SKILL.md:59-66`). This means one command, already run, that asserts the user's exact symptom, is deterministic, and can run unattended. Why: it gives a debug gate that is binary and can be checked, not left to judgement.
3. **The `undefined`-import test-quality check** (`pstack/skills/principle-test-behavior-not-implementation/SKILL.md:11-21`). The rule names five failing shapes, and A's "tautological" anti-pattern says the same (`mattpocock_skills/skills/engineering/tdd/SKILL.md:31`). Why: it gives a cheap, mechanical way to delete tests that cannot fail for a defect.
4. **Two review axes that are never merged or reranked** (`mattpocock_skills/skills/engineering/code-review/SKILL.md:76-87`) combined with **agreement across models as the strongest signal and a 4-bucket verdict from the lead** (`pstack/skills/interrogate/SKILL.md:64-80`). Why: separate axes stop one kind of finding masking another, and model diversity replaces assigned personas as the adversarial signal (l.9).
5. **A fact or decision classifier before asking the human.** Facts are the agent's to find, through a subagent or a prototype. Only preference calls go to the user (`mattpocock_skills/skills/productivity/grilling/SKILL.md:26`; `pstack/skills/poteto-mode/SKILL.md:20`). Why: both repos arrived at this independently, and it cuts questions the human should never have been asked.
6. **Fresh subagent by default, with consolidated scope.** The new agent gets the original brief, every later directive, and the prior agent's report and branch. Resume an agent only for state that is costly to move (`pstack/skills/poteto-mode/SKILL.md:99`). Pair this with orchestrate's standing orders pasted verbatim into every spawn (`playbooks/orchestrate.md:8-10`). Why: it names how directives decay across resumes and gives a concrete fix.
7. **A structure lint for plan documents** (`pstack/skills/poteto-mode/scripts/check-plan.mjs:5-25`, used at `playbooks/multi-phase-plan.md:10`). It checks required sub-blocks per PR and a verification sentence that must appear verbatim. Why: a plan template that a script checks does not drift, while a prose template does.
8. **A decision log audited against the transcript, then reviewed by another model family.** It is append-only, and rows are superseded rather than edited (`pstack/skills/show-me-your-work/SKILL.md:52-74`). Why: it makes unattended runs auditable, and it catches invented rows because the audit compares claims with what actually happened.

Notable runners-up: A's "fog or ticket" test (`wayfinder/SKILL.md:88`); A's rule that the reviewer, who has less context pressure, enforces standards rather than the implementer (`retro/SKILL.md:71-75`); B's 5-rung proof ladder (`blast-radius/SKILL.md:21-28`); A's context-pointer and no-op pruning theory (`writing-for-agents/SKILL.md:12-18,82`).

Caveats (judgement): B is coupled to Cursor (the `Task` tool's `environment: "cloud"`, `.cursor/rules`, the built-in `create-skill`, and the companion plugin `cursor-team-kit` for `deslop`/`control-ui`). Its specific model slugs and autonomy defaults ("Just do it", `poteto-mode/SKILL.md:83`) would not carry over unchanged. A depends on an issue tracker for its flows, and `implement-spec` and `retro` are new in this release and short (40 and 44 lines), so they are less proven.
