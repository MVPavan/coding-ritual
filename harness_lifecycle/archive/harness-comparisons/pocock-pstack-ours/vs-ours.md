## 2. Borrow candidates (ranked; smallest durable version)

1. **The "subject returns nothing" test check.** Source: `cursor_plugins/pstack/skills/principle-test-behavior-not-implementation/SKILL.md:11-21`.
   - Change: `.claude/skills/test-driven-development/references/writing-good-tests.md` after l.22. Add: "Before keeping a test, ask whether it would still pass if the subject returned nothing. If yes, it catches no defect: rewrite the assertion or delete the test."
   - Why: it turns the existing "identify the wrong branch it catches" (l.22-23) into a check you can run in your head. It also fits the lean-tests direction and the E2E rewrite's "list failure modes first".
2. **No hypotheses until a reproduction has been run.** Source: `mattpocock_skills/skills/engineering/diagnosing-bugs/SKILL.md:59-66`.
   - Change: `.claude/skills/systematic-debugging/SKILL.md` step 1 (l.14-18). Add: "Before forming hypotheses, run one command that shows the reported symptom and record its output. If none is obtainable, say so and use the no-reproduction path (l.35)."
   - Why: it gives the step a completion criterion you can check. Today the step can be skipped by reasoning from the code.
3. **Name the shared premise after two failed fixes.** Source: `cursor_plugins/pstack/skills/principle-attack-the-premise/SKILL.md:14-21`.
   - Change: `systematic-debugging/SKILL.md:44-45`. Extend the existing stop rule with: "state the premise both fixes assumed and the evidence that would refute it."
   - Why: it is one clause on an existing gate, and it turns "stop" into a concrete next probe.
4. **Prefer the strongest enforcement and record what enforces each lesson.** Source: `cursor_plugins/pstack/skills/correct/SKILL.md:19-30`; `principle-encode-lessons-in-structure/SKILL.md:19`; A's `retro/SKILL.md:59`.
   - Change: the header of `.repo-context/learnings.md` (l.1-5). Add: "When a lesson recurs and is mechanically checkable, add the check (verification.md or invariants.md) and cite it as the evidence; keep prose only for judgement calls."
   - Why: `authoring-for-agents/SKILL.md:20` already lists hooks and checks as a place to put rules. This closes the loop for lessons. J: there is no need for B's full rule-to-enforcer table yet.
5. **A safety claim backed by running code.** Source: `cursor_plugins/pstack/skills/blast-radius/SKILL.md:21-37`.
   - Change: add one row to the claim → evidence table in `.repo-context/verification.md:13-19`: "Change is safe for callers | The load-bearing fact shown by executing the real code | A written argument or caller list".
   - Why: it fits our existing claims format and needs no new skill.
6. **Facts you can observe are not the user's to answer.** Source: `cursor_plugins/pstack/skills/poteto-mode/SKILL.md:20`; `mattpocock_skills/skills/productivity/grilling/SKILL.md:26`.
   - Change: `.claude/skills/grilling/SKILL.md:16`. Add: "A question settled by running something (behaviour, output, timing) is a fact: answer it yourself or via prototype."
   - Why: it is consistent with `AGENTS.md:9-10`, which says to ask only on material ambiguity. It reduces wasted questions.
7. **Tell the agent to load a skill, not just mention it.** Source: `mattpocock_skills/.agents/invocation.md` ("Dependencies between them"); `CHANGELOG.md` 1.3.0 #878/#880.
   - Change: `.claude/skills/authoring-for-agents/references/skill-anatomy.md`. Add: "When a step needs another skill, instruct loading it ('load the review skill'), never by bare mention; a skill cannot rely on loading a manual (disable-model-invocation) skill: tell the user to run it."
   - Why: ours writes references like "(review skill)" (`systematic-debugging/SKILL.md:46`). J: A gives no measured evidence that this works ("intended to raise the hit rate"), so treat it as a hypothesis to trial.
8. **A plan-structure lint.** Source: `cursor_plugins/pstack/skills/poteto-mode/scripts/check-plan.mjs:5-25`.
   - Change: a new `--check` script for the headings in `planning/references/plan-format.md`.
   - Why: it would stop plan templates drifting. J: **defer** until plan drift is actually seen. Add it only with that evidence.

## 3. Reject / defer

- **Sticky mode, playbook router, and copying steps verbatim into todos** (`poteto-mode/SKILL.md:5-8,121`). Reject. This violates our "no sticky single mode" rule. Our `skill-router` is optional by design (`skill-router/SKILL.md:8-10`).
- **Per-role model rule and hard-coded model slugs** (`setup-pstack/SKILL.md:39-66`; `interrogate/SKILL.md:38-42`). Reject. Our shared semantics must stay provider-neutral (`authoring-for-agents/SKILL.md:22-23`).
- **"Just do it" autonomy and proceed-then-present for external actions** (`poteto-mode/SKILL.md:83`; `principle-never-block-on-the-human`). Reject. It conflicts with `AGENTS.md:11-12`, where messages and publishing need authorization.
- **`swarm` / `arena` / `interrogate` as defaults** (`architect/SKILL.md:31-35` runs arena on every design). Reject as defaults. Our council is explicit-only (`model-council/SKILL.md:3`). J: arena's "pick a base and graft from the others" step could be a note in model-council later.
- **Fresh subagent for every fix round** (`poteto-mode/SKILL.md:99`). Defer. It conflicts with the recorded feedback that resuming is cheap and preferred. The compatible part, standing orders kept in every brief, is already covered (learnings "Assembled briefs").
- **TSV decision log plus a cross-model review of the log** (`show-me-your-work/SKILL.md:52-74`). Defer. Unattended runs already produce ledgers and receipts in code (`docs/usage/children.md:26-28`). A prose log would duplicate them.
- **`implement-spec` worktree fan-out** (`implement-spec/SKILL.md:27-36`). Reject. The foreman contractor already owns this in code (`execution/SKILL.md:65-78`).
- **`pr` template / `opening-a-pr`**. Defer. We have no PR flow and no CI (`verification.md:8-9`).
- **Fowler smell baseline in review** (`code-review/SKILL.md:38-56`). Defer. Smells are preference-level, and ours excludes preference as a finding (`review/SKILL.md:23`). Expect noise.
- **`retro` / `reflect` as skills**. Defer. Candidate 4 covers the durable part. A transcript-mining skill would need its own authorization rules for memory writes (`AGENTS.md:28-30`).
- **Renaming CONTEXT.md to GLOSSARY.md**. Reject. Our glossary location is `.repo-context/CONTEXT.md` by convention (`domain-modeling/SKILL.md:12-14`). Renaming is churn with no behaviour change.
- **`create-verification-skill`**. Defer. We have no user-facing app. Revisit if the E2E-default TDD needs a reusable harness for driving the interpreter CLI.
- **`unslop` rule catalogue / em-dash bans**. Reject. This is style preference, and B's rule 13 contradicts its own parentheses usage elsewhere. It does not change agent correctness.

## 4. Things ours does better

1. **Reviews have verdict contracts and track fix rounds.** Separate spec and quality outputs, ADDRESSED / NOT ADDRESSED per finding, and a "plan-mandated" label (`review/references/review-contract.md:13-45`; `review/SKILL.md:15-25`). A's review stops at a report (`code-review/SKILL.md:74-78`). B's lead buckets findings but does not track them across rounds (`interrogate/SKILL.md:75-80`).
2. **Orchestration lives in code, not prose.** The contractor claims, lands, and closes stages, with defined result states (`execution/SKILL.md:65-78`). A and B rely on the model following prose playbooks (`implement-spec/SKILL.md:19-40`; `orchestrate.md`).
3. **Claims need named evidence.** The claim → evidence table, with a "Not enough" column and `PARTIAL` reporting (`.repo-context/verification.md:11-22`), is more explicit than A's embedded criteria or B's principle prose (`principle-prove-it-works/SKILL.md:9-16`).
4. **Authority is explicit throughout.** Analysis requests authorize only reporting (`AGENTS.md:7-8`), and skills restate their write gates (`grilling/SKILL.md:22-24`; `domain-modeling/SKILL.md:44-46`; `improve-codebase-architecture/SKILL.md:9-11`). A has no authority model, and B defaults to autonomy (`poteto-mode/SKILL.md:83`).
5. **Lessons carry evidence and a revisit condition.** `.repo-context/learnings.md` rows cite an incident and say when to recheck (for example the "Flaky-test claims" and "Marked pytest lanes" rows). B's `reflect` routes lessons into skill edits with no expiry or revisit (`reflect/SKILL.md:51-63`).
