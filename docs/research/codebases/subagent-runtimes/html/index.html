Subagent runtime anatomy

How Claude Code 2.1.217 and Codex 0.144.4 discover an agent, combine its metadata with an invocation, construct a child runtime, and persist the result.

The matrix should perform a join, not store a product. Role, capability policy, execution profile, and invocation context change independently. Claude and Codex bind them at different stages.

The four things currently hiding inside “agent”

1. Role

Identity, routing description, stable instructions.

Researcher, API developer, explorer.
2. Capability

Tools, MCP, skills, permissions, isolation.

Read-only, networked, worktree.
3. Execution

Runtime, provider, model, effort, service tier.

Claude Sonnet/high or GPT/Terra/medium.
4. Invocation

Task, context fork, background mode, limits.

Fresh, full history, last N turns.

Claude

Definition is a manifest

  1. Resolve model from environment, invocation, definition, parent.
  2. Inherit parent permissions; apply allowed definition mode.
  3. Resolve inherited tools, definition allow/deny, MCP additions.
  4. Apply definition effort or inherit session effort.
Important asymmetry

The Agent call can choose a model but has no shipped per-call effort field. Arbitrary effort routing requires definition/session variants.

Codex

Role is a config layer

  1. Clone parent turn config.
  2. Validate and apply invocation model/effort.
  3. Apply named role Config; overlapping values now win.
  4. Reapply parent approval/profile/cwd boundary.
Important asymmetry

A role containing model or reasoning effort locks it. Leave those keys out when the matrix chooses the execution profile at launch.

Codex V2 full-fork trap. Omitted fork_turns defaults to all. A full fork rejects agent_type, model, and reasoning_effort. To select a role/profile, pass fork_turns: "none" or a positive turn count.

requested_effort: medium
effective_permissions: read-only
runtime_agent_id: ...
Adapter invariant. Record requested and resolved settings separately. Parent policy, allowlists, role pins, fork mode, and session tool exposure can all change or reject the request.

Version-sensitive gaps to settle before implementation

Claude depth contradiction

Docs say depth five is fixed. The exact binary contains a depth environment variable and error text suggesting it can be raised. Treat five as supported until a controlled probe proves otherwise.

Codex schema drift

Current docs describe default subagent model/effort keys absent from the tagged 0.144.4 AgentsToml. Version the adapter.

Codex V2 depth

V1 enforces configured depth; 0.144.4 V2 always exposes collaboration tools and lacks the same handler check. V2 is marked under development.

Portable capability enforcement

Claude has per-agent tool lists. Codex roles do not expose an equivalent schema. The adapter must prove restrictions or fail visibly.
