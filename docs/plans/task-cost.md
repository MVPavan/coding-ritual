# Task cost reporting implementation plan

*Names (2026-09): phase bridge → contractor, supervisor → inspector, runner → crew; citations below use the old names.*

Stage: cr-7uhd.1 (execution epic cr-7uhd).

Approved scope: cr-02ze.8, task-level token and API-equivalent cost reporting. Read-only reporting; no scheduling, sandbox or landing behavior changes. Implementation through Sol high / Opus medium workflow after current pointer-handoff lands.

Deliver one CLI and typed library under workflow_interpreter/costs/ (models, pricing, collection, report, __main__ split only as needed), focused tests/test_task_cost.py and docs/usage/task-cost.md, plus a dated standard API pricebook under config/. Prefer existing BdClient/read functions and root/activation carriers over a new persistence layer. No new DB or dependencies. Optional tiny foreman routing glue only if materially simpler; primary CLI is python -m workflow_interpreter.costs --config FOREMAN_CONFIG --prices PRICEBOOK task STAGE_ID [--format json|text]. A cohort command takes explicit task IDs; no unbounded repository scan.

Collection: read task phase_bridge metadata, find_roots for its current instance_key plus previous_attempts, then list activations from every matching root. Include abandoned, superseded and failed work; never choose only successful/latest root. Deduplicate root/activation identities and refuse identity conflicts. Completion requires stage closed with valid bridge closed/landing metadata and landed OID; closed task alone or shipped root alone is insufficient. Unknown or unsupported completion contracts stay explicitly unverified. Human gates consume no assumed LLM tokens. Preserve requested model, resolved effort/role, activation lifecycle/outcome, timestamps when actually available, and source record references. Report unavailable timing honestly.

Use normalized durable activation usage as baseline. For richer accurate costing, optional explicitly configured runtime roots allow reading existing launch receipts/exec ledger/run.jsonl (never keys or arbitrary prompt content in output). Enrich only terminal usage/modelUsage events, model identity and cache TTL/service tier. Decode stream incrementally with finite byte/event limits and diagnostics for malformed/truncated/oversized logs. Log absence falls back to baseline with missing coverage flags. Do not add baseline totals to enriched totals: select one authoritative representation for each execution, reconcile where possible. Handle Codex total input subsets, Claude cache read/write TTL, output including reasoning, and auxiliary modelUsage entries. Distinguish requested and observed model identity; price unknown identities only with explicit pricebook mapping and provenance. Multi-exec/resume data must use stable event/session/exec identities and appropriate cumulative-counter semantics; when boundaries cannot be proved report incomplete rather than sum blindly. Duplicated results must not inflate cost. Log-derived observed model is telemetry, not proof of backend identity.

Allow explicit external attribution via a strict versioned usage supplement file: unique record ID, task ID, optional parent/child task association, source reference, model/effort/role, token categories and measurement semantics. This covers coordinator/planning calls and child workflows not represented in phase_bridge. Never imply global chat spend is automatically captured. Exact same record included twice deduplicates; conflicting duplicates fail. Cohort rollups union underlying usage identities so parent/child records cannot double count. Task sharing requires explicit ownership; do not guess allocation. Unattributed coordinator/child usage is listed as uncovered scope, making whole-task totals partial even if all engine calls are known.

Pricebook: strict versioned JSON, currency USD, snapshot retrieval/as-of date, official source URLs, model IDs, service tier, uncached input/cache read/cache write TTL/output rates as decimal strings per 1M. Nonnegative finite amounts only, no binary float arithmetic. Initial standard prices verified 2026-09-13: Terra 2/.2/12, Sol 4/.4/20 input/cache-read/output, Opus5 5/.5/25 with 5min write6.25 and1h write10; Claude Haiku4.5 1/.1/5 with write1.25/2 (verify official before committing). OpenAI cache write pricing must be verified or left unavailable where telemetry is nonzero; never assume base input rate. Rates for unlisted tiers/models/unknown TTL remain missing, or a clearly labeled user-selected standard-rate normalization; do not claim actual billing. Pricebook may hold multiple dated snapshots: explicit --as-of selects common-date repricing, --run-date selects latest applicable snapshot only if source effective dates and execution dates support it; absent historical rates stay unavailable, never silently use current prices. Preserve vendor-reported costs separately, never use them as a substitute for today-price repricing. Subscription costs are unknown.

Output: per-task status/completion evidence, roots/attempts, activations/review rounds, role/model subtotals, raw token categories, known priced subtotal, missing usage/rates and coverage, attributed/unattributed scope, durations when measurable, pricebook date/hash and source references. Expose whole-task cost only if coverage is complete; otherwise label partial observed spend, never zero. JSON and concise human text. Cohort mean/median completed-task cost only over completely measured comparable completed tasks with denominator and excluded counts; separately success rate and total cohort observed spend / completed count, labeled partial when any coverage is incomplete. Zero completions returns null, not division error or $0. Mixed-model tasks stay mixed; no causal model ranking from unmatched workloads.

Test-first: synthetic Beads/activation fixtures across failed then successful roots; actual CLI test through supported read seam; duplicate/resumed/cumulative reset/truncated log cases; auxiliary models; cache TTL/output subsets; missing versus zero; Decimal exactness; dated repricing; incomplete task/completion gating; cohort failure spend and parent-child dedup. Read-only guarantees: collector invokes no writes or launches and needs no network. No live paid model calls. Live smoke after landing: report cr-wi82.1 with all four attempts; explicit runtime-root mappings for differing historical wrapper locations if needed. Save report as evidence, note external coordinator usage unavailable. Repeated read must be stable apart from documented generation timestamp.

Verification: new focused host script runs test_task_cost.py plus relevant existing usage/profile/bridge CLI tests, Ruff/format and strict mypy. Provision interpreter before model launch. Models run only that named focused set excluding live/bd/nested_sandbox/proc markers as appropriate; do not run the entire suite in activation. Host pinned full bridge verifier is the final gate. Two implementation entries; no coordinator source patches; Opus review and signed ship before isolated landing. Pricebook and docs are owned artifacts and must remain present after rework.

## Resolved independent plan critique
1. Collector invariants: token counts must be integers >=0 (bool is invalid); money must be finite Decimal >=0. Null means unreported, zero means measured zero, and known=True never implies completeness. Invalid legacy values must not be summed or priced: attach explicit diagnostic and mark coverage incomplete. Do not modify the global Usage wire carrier or silently coerce invalid values.
2. Dedicated profile-specific raw-log adapters live in costs/. Every observation has provider/profile, root/activation, launch/session identity when proven, event/request identity or terminal turn identity, model and measurement kind terminal-cumulative or step-delta. Stable IDs deduplicate; identical duplicate observations count once; conflicting duplicates are invalid. Claude result uses modelUsage per-model totals when present, does not add top-level totals a second time; cache TTL comes from raw usage only when attribution is unambiguous. Codex turn.completed totals are per terminal turn/execution as evidenced, reasoning counts are subsets. Opencode step-delta support must be backed by known profile semantics/tests; otherwise mark unsupported/incomplete. A resumed session without provable execution/counter boundaries cannot yield a complete sum. Do not derive rich cost facts from the lossy Usage carrier alone.
3. Completion predicate: stage status closed AND parsed phase_bridge.state CLOSED AND current root_id, landed_oid, tree, gate_receipt_digest and landing_receipt_digest all nonempty/valid. Current and every prior instance_key must resolve exactly once to a root with the same instance key and correct trusted stage/epic identity relationship; ambiguity/missing roots makes coverage incomplete and completion unverified. Cross-check available final root/landing evidence for contradictions; report completion basis, do not claim cryptographic verification beyond checks actually performed. Include tests for forged closed flag, missing landing fields, mismatched root, and duplicate root identities. Historical record migration is outside scope; unsupported historical records report unverified rather than being rewritten.
All three findings are resolved by these explicit implementation/test contracts. Remaining pricing and cohort design unchanged.
