## Task 1: Consistent leaf execution contract

Produces: one engine-owned mandatory contract delivered and budgeted on first launch and on continuation/resume; provider-neutral delivery without new vendor configuration flags.
Approach: put concise leaf duties with mandatory fact-frame/protocol content before optional budgeted data. Direct implementation/review/test work follows applicable repository coding rules, but generic repository delegation/execution instructions do not assign coordination authority to this node. Enclosing engine owns reviewers, routing and gates. Do not invent an escape clause based on arbitrary task prose. Existing coordinator admission/collection APIs remain available at their current trusted surface; membership alone is not a node delegation grant. Compose continuation advice into the actual delivered envelope at the shared seam; do not append unrecorded content after budget accounting. Retain task identity, node contract and original intent on resume. Keep unsupported OpenCode launch/resume refusal unchanged. Avoid a new graph-schema capability solely for this fix; preserve canonical old graph bodies.
Verification: initial and resumed serialized CLI command payloads contain mandatory contract and original intent; steer advice remains; retry-from-continuation does not bypass it. Contract survives trimming or produces honest input-budget refusal. Conflicting generic delegation prose does not remove the mandatory contract. Assert existing explicit coordinator child admission tests remain green.
Test seams: actual envelope/dispatch/profile serialization APIs; use synthetic CLI stubs, no paid model tests inside nodes. A separate bounded live behavioral probe may validate cooperative instruction adherence, not establish hard isolation.
Dependencies: none.
Risk: test-first. Prompt composition may change capacity or duplicate material; delivered and recorded bytes must agree. Never silently trim required context or weaken input limits.

## Task 2: Producer-linked interrupted-work evidence

Goal: unfinished tracked edits and non-ignored untracked files are durably recoverable before another activation reset, with discoverable producer identity.
Consumes: confirmed-dead writer activation, trusted workspace ownership/band, existing snapshot/ref operations and exit/recovery/steer lifecycle.
Produces: idempotent producer-linked recovery reference and visible evidence, without a verified artifact or accepted outcome.
Approach: characterize current behavior first. Terminal cleanup already retains dirty worktrees and pre-reset snapshots already protect later resets. Do not label those paths data-loss bugs. Close the earlier durability/discovery gap by reusing snapshot logic. Only snapshot owned writer workspace after proof of termination and under existing coordination/locking; read-only/clean/no-change exits need no unnecessary snapshot. Cover normal exit with dirty work, timeout/error, dead-without-exit recovery and steer. Persist evidence before grading/close, make failure explicit and retryable, and retain original files on failure. Existing snapshots and lineage remain intact. Recovery ref must not enter candidate selection, success outcomes, trusted writer lineage or retry base derivation. Pin integrity and identity validation must follow current mechanisms; replay must preserve prior snapshots without overwriting divergent content. New optional carriers remain backward-compatible with old records.
Scope: existing snapshot content semantics only: worktree tracked content and non-ignored untracked files. No promises for ignored files, nested repositories, special files or separate staged/unstaged reconstruction. No automatic restore or promotion; document a supported read-only way to inspect the ref and paths. Unknown interrupted/nested token usage stays unknown; do not add inferred telemetry or broaden cost reporting in this slice.
Verification: killed writer with tracked/untracked content has producer-linked recoverable bytes before retry; replay is idempotent; pin failure leaves work intact and cannot report completed preservation; retry/reset/terminal behavior retains recovery; no candidate means verification remains at original base. Cover dead-without-exit and steer narrowly. Foreign or live writer content is not snapshotted or modified by an unauthorized operation. Preserve existing snapshot chaining and pin-failure tests.
Dependencies: none at source level; delivered together with Task 1 in one reviewed candidate.
Risk: test-first. Boundary assets are user work, untrusted model outputs and accepted Git artifacts. Use existing authority and atomic pinning; no new authority from model-created paths or records.
