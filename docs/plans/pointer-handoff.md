Concrete decisions after plan critique:
- Graph contract: task-node field artifact_input_mode, optional enum "inline" | "references". Absent/None means inline; omit None from canonical serialization so old canonical bytes/hashes remain unchanged. Treat it as graph-authored semantic configuration, not a new project/CLI override. Reject on gate/terminal nodes and reject invalid enum values. Propagate the effective mode to TaskSpec only as needed for reviewer permissions, with legacy-default behavior unchanged.
- Pointer wire text: a compact JSON object in the labeled artifact input, with repository_path, base_commit, candidate_commit, candidate_tree and optional reports_tree for writers; output-only producers use repository_path and reports_tree. OIDs are full immutable Git IDs. Path discovery/read recipes are role instructions: git -C <quoted-repository> diff --no-ext-diff --no-textconv <base> <candidate> --; git -C <quoted-repository> ls-tree -r --name-only <reports-tree>; git -C <quoted-repository> show <reports-tree>:<chosen-path>. Do not interpolate a report path into an executed shell command; engine Git operations use argv. Paths containing unusual characters must not become instructions or change identity. No eager diff, blob contents or full path list in the pointer envelope.
- Deterministic proof before dispatch: existing binding producer/ref/digest equality; writing ref resolves exactly candidate_commit; Git resolves candidate_commit to candidate_tree matching binding.digest; base resolves as an existing commit and is an ancestor of candidate. For outputs, existing producer evidence ties outputs_ref to outputs_tree_oid; resolve the ref's actual tree and require equality before rendering reports_tree. Reject missing objects, mismatches, moved pins and invalid references through existing refusal handling. No requirement to mint new Git objects or alter existing output publication.
- Reports remain the existing supervisor-published output snapshot (no new storage format). Discover report paths by ls-tree on reports_tree, read blobs by that tree ID, and verify in tests after original filesystem reports are removed/changed. For writers without published outputs, omit optional reports_tree explicitly; if evidence claims an output pin, validate it rather than silently omit broken evidence.
- Claude reference-mode read-only reviewers: include Bash in available tools and allow Git inspection using existing permission matching, keep push denials, and retain writable report channels only at the outer sandbox. Legacy inline reviewers retain their old tool set. Reference-mode shell-capable reviewers require the outer bwrap boundary; refuse unsupported sandbox-off rather than silently grant a shell without that boundary. Test an actual shell with Git diff/show/ls-tree through the production read-only plan, alongside denied writes to source, Git config/refs, wrapper metadata and sibling checkout; cover launch and resume argv. Do not make read-only a prompt-only promise.
- Large-input regression uses >80 KiB diff text and a final serialized UTF-8 envelope <=32768 bytes with the complete original task brief. Instrument the Git seam to fail if reference mode reads full diff/blob bodies. Keep the original inline path's overflow behavior as a control and exact legacy canonical fixture roundtrip/hash checks. Verify an old pinned root can still build launch/resume task inputs without migration.
