# P5 Implementation Plan — Normal Execution and Trusted Successors

**Origin:** approved coordination specification; P3/P4 handoffs and P5 critique.
**Goal:** expose ordinary design, independent work, decisions, integration, and closure through the normal CLI; add bounded same-graph and trusted changed-graph successors; prove one assembled Claude/Codex path.
**Stage:** every task serves `cr-thh.1`.
**Dispatch:** await P4 exit and independent P5 plan critique. Full gates and final Fable review are exit evidence.

## Authority and fixed boundaries

P1 retains pinned checks, authenticated human ship gates, target CAS, receipts, and forward recovery. P2 retains identity-bound decisions, essential context, and finite reservations. P3 retains child lifecycle, cancellation, and current-child records. P4 retains same-owner immutable selected sources, fixed `integration_sources`/`stage_brief`/`target_base`, target claims, associations, and phase-aware landing guards. No child DAG, automatic downstream binding, provider, runner, database, signing authority, or model-selected changed-pins successor is added.

P4 functions are `prepare_integration`, `resume_integration`, `retry_integration`, and `prepared_for_stage`; its saved association enters P3 through `start_child`. P5 calls and extends these seams rather than recreating P4 persistence. `retry_integration` remains same-pins only.

### 3. Wire integration and one durable successor transition

**Files:** create `foreman/replacement.py`, `tests/test_replacement.py`, `tests/test_integration_cli.py`, `tests/test_bridge_successor.py`; modify `foreman/__main__.py`, `foreman/decisions.py`, `foreman/children.py`, `bdio/coordination.py`, `schema/decisions.py`, `bridge/models.py`, `bridge/adapter.py`, `bridge/integration.py`, `bridge/command.py`, `docs/usage/phase-bridge.md`, `.claude/skills/execution/SKILL.md`, `config/foreman.example.toml`.

Add `integration prepare --request FILE`, `integration status EPIC STAGE`, and `integration retry EPIC STAGE`. Prepare validates `IntegrationRequest` then calls `prepare_integration`; status reads `prepared_for_stage`, `IntegrationGuard.association`, and P3 `child_status`; retry loads the stored record then calls `retry_integration`. Existing `phase-bridge`, `children`, and `--retry-landing` retain their meanings.

Define one durable `advance_successor` used by P2 same-graph replacement, ordinary coordinated-bridge replacement, and the trusted operation. It fences owner → predecessor member (plus target lock for a bridge), proves every process settled/dead, persists intent/binding before admission, reserves against the original owner limits, admits/binds the successor, updates the current child record, and replays its receipt/lineage after a crash. A repeat with the same durable key/digest returns that successor before checking the caller's stale generation; a changed key or payload refuses.

`children replace OWNER --slot SLOT --generation N --request FILE` is the only changed-graph/config/model-pins authority. `TrustedReplacementIntent` stores its key/reason/expected generation/request digest, canonical graph and `_resolved_config` identities/bytes, resolved admission, predecessor/root, and immutable successor lineage. P2 `replace` retains the original graph/config pins and changes only its declared advisory input; it invokes `advance_successor`, not this command. Legacy roots without an admitted coordination record refuse.

Its protected `obligation_digest` canonically covers required instance-source names and writer/reviewer consumers; verifier/check policy; ship-gate identity and approve/abandon bindings; allowed write scope; and graph reachability proving every successful writer path crosses the protected reviewer then ship gate. The candidate graph must match every field and cannot add a successful-writer bypass. This is structural preservation only: every successor still receives fresh ordinary review, checks, and gate handling.

Supported successors are standalone non-bridge work; uncollected P3 children not consumed by P4; coordination-enabled ordinary bridge members; and P4 integration roots. All refuse cancellation, unrelated pending/consumed decisions (the matching bound P2 replacement decision remains replayable), open or abandoned human gates, missing capacity, changed required source, candidate authorization, landing intent/receipt, or observed/pending landing. Source-bearing children cannot be replaced after their receipt is bound to an integration association.

For an ordinary bridge successor, persist and validate its owner/member/admission/request binding against the old bridge record, then fence the predecessor and write a prepared successor record before root admission. Preserve stage target CAS base **B** in the bridge record; permit successor execution base **A** only when it is the validated predecessor artifact, and land **C** only by CAS **B → C**. Direct/recovery landing or close of the predecessor refuses; global legacy instance-key/base rules remain unchanged.

For an integration changed-pins successor, add `replace_integration` beside—not inside—same-pins `retry_integration`: under `IntegrationGuard.ordered`, persist a successor association with predecessor digest, canonical protected admission, and fresh generation; atomically revalidate/transfer the active target claim; prepare the P1 successor record; call P3 `start_child`; save the root receipt/binding; then admit the record. Replay re-finds that association; predecessor bridge/landing/close refuses. Preserve exact source receipts/manifest/brief/base bindings, target claim, verification policy, and required integrate/review path; reject source or slot remapping.

**Tests:** CLI direct calls and checked admission; identical trusted-command replay after advancement and changed-payload refusal; two distinct graph/config bodies with fresh pins/generation/reservation and immutable predecessor bytes. Cover every crash point in each successor order, stale predecessor result/approval, gate/abandonment/cancellation/budget/source/landing fences, protected-digest bypass attempts, and renewed review/check/ship. Prove P2 same-graph replacement updates child and ordinary-bridge bindings; prove ordinary bridge **B → A → C** and CAS **B → C**; prove P4 association/claim/bridge binding at each crash boundary. Deterministic tests suffice for replacement semantics.
