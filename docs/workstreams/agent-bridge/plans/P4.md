# P4 Implementation Plan — Fresh Integration

**Origin:** approved coordination specification; roadmap P4; P3 implementation handoff.
**Goal:** turn an explicit set of collected P3 results into one freshly reviewed integration workflow, then let the existing authenticated bridge land only that current artifact.
**Stage:** every task serves `cr-3zz.1`.
**Dispatch:** await P3 full gates, grouped Fable review, and independent P4 plan critique.

## Scope and existing authority

P3 provides `start_child`, `child_status`, `collect_child`, `cancel_child`, `recover_child`, and `drive_children` through `composition.store.coordination_store(composition=composition)`. Its `CollectedChildResult` is immutable evidence, not landing authority. P4 reuses that Beads-backed `CoordinationState`, P1 `PhaseAdapter` stage claim/close, and P1 `PhaseLanding` gate/check/CAS/receipt recovery. There is no child DAG, automatic downstream binding, new database, framework, runner, or graph/model replacement.

The orchestrator explicitly selects every required source as `(slot, generation, receipt_digest)`. Sources and the integration member have the same P3 owner. It selects no next child automatically. P4 records this source set once; it never infers it from slot names, dependency edges, or a final activation label.

## Durable records and minimal wiring

Add strict, null-elided `IntegrationAssociation` to the existing owner `CoordinationState`: owner/stage identity, request key/digest, target-claim key, state (`prepared`, `root_bound`, `admitted`, `landing_authorized`, `landed`, `stale`), ordered required-source receipts, fixed manifest digest, target ref/base, pinned `MemberAdmission` digest, integration slot/generation/root receipt, bridge-record digest, and P4 landing-authorization digest. It is the source-set authority. Add only its digest and owner/slot/generation to `PhaseBridgeRecord`; existing P1 records remain readable.

`IntegrationTargetClaim` is one existing-Beads metadata record keyed by `sha256(canonical_repository_identity + target_ref)`. Under its canonical workspace lock, it stores the active owner/stage/attempt/association digest and a recoverable disposition. Acquire and persist it before snapshotting the target; an unequal live attempt returns bounded `busy`. The lock is short; the durable claim remains through execution and is released only on terminal retirement or atomically transferred to the same owner's explicit retry. No second database or target scheduler exists.

`prepare_integration(composition, request) -> PhaseBridgeRecord` is the one P4 admission path:

1. Reload every selected P3 child and require its exact current `collection`, no cancellation, matching root/generation/receipt, and accessible immutable commits/trees.
2. Derive a repository contribution from the source root's pinned graph, resolved settings, and activation artifact evidence. A source counts when a resolved node wrote, including tracked Markdown under `docs/`; a final reviewer/reader receipt with `artifact_source="activation-input"` does not erase an earlier writer's contribution. Refuse missing writer artifact evidence or an artifact/tree mismatch.
3. Under target-claim exclusion, snapshot the target and build a canonical, untrimmable `integration_sources` manifest containing every selected receipt/tree/ref, plus fixed non-optional instance sources `stage_brief` and `target_base`. Pin all three in `MemberAdmission.essential_inputs` with writer/reviewer consumer bindings before root creation; P2 root and envelope limits apply before dispatch.
4. Persist/read back the `prepared` association and P1 prepared bridge record before `start_child`. Then call P3 `start_child(owner, integration.<stage>.<attempt>, admission)`, persist/read back the receipt binding, and call `PhaseAdapter.admit` with that same root. This consumes one whole-member `kind="child"` reservation against the original owner.
5. Recovery reuses the prepared slot/admission digest to find the one P3 receipt, then repairs root binding or bridge admission. No `WorkflowRootProvisioner` call, recreated root, second capacity ledger, or changed prepared payload is allowed.

The P4-specific bridge binding accepts the P3 receipt root, not P1's legacy `instance_key` lookup. It validates the exact owner, slot, generation, receipt digest, and active root on every use. `PhaseAdapter` remains the only stage-close authority; `CoordinationStore` remains the only member-admission/capacity authority.

## Tasks and ownership

### 1. Admit an explicit integration root

**Files:** create `workflow_interpreter/bridge/integration.py`, `tests/test_integration_admission.py`; modify `schema/decisions.py`, `bdio/coordination.py`, `bridge/models.py`, `bridge/adapter.py`, `bridge/command.py`.

Implement `IntegrationRequest`, `IntegrationAssociation`, `IntegrationTargetClaim`, and `prepare_integration`. The normal `execute_phase_bridge` admission route consumes an already prepared association and resumes its integration root through the existing `Foreman`; P5 owns operator-facing command documentation. Keep all input/source bytes and receipt digests pinned before root creation. Use a new stage-attempt slot for an explicit stale/conflict retry; retain the same graph/config unless P5 authorizes substantial replacement.

**Tests:** identical request replay has one root/reservation; changed request-key payload, stale generation, cancelled/uncollected source, duplicate/missing source, wrong repository/tree, changed pin, and exhausted owner capacity refuse. Fault association prepared → bridge prepared → child receipt → bridge admission and repair only the saved root. Two owners for one repository/ref prove one durable active claim and one bounded busy result before either snapshots the base; retry transfers the same claim without a gap.

### 2. Execute and verify a fresh combined tree

**Files:** create `workflows/integration.toml`, `tests/test_integration_lifecycle.py`; modify `bridge/integration.py` and only the necessary integration fixtures.

The graph is ordinary worktree `integrate` writer → non-writing `review` → existing authenticated ship gate, with finite bounds and pinned checks. Both nodes list fixed non-optional instance sources `integration_sources`, `stage_brief`, and `target_base` in `inputs`; `review` additionally lists its non-optional, pinned activation-produced `candidate_diff`. No arbitrary caller input names or per-path writer manifest exists. P1 verification policy, repository checks, and human ship authority apply unchanged. A changed candidate requires fresh review, checks, and ship evidence.

**Tests:** canonical manifest contains every receipt/tree/ref and is required for both nodes; root/envelope oversize refuses before admission. Two same-base sources (one Markdown write) plus an independent target change produce a candidate preserving all three. Prove a final reader collection whose `artifact_source` is `activation-input` still contributes when its root contains a validated writer artifact. Refuse partial writes, missing/failed checks, review of another tree, stale source evidence, reused child approval, and same-file conflict without a reviewed resolution. No test injects candidate, gate, or landing success directly.

### 3. Guard landing, recovery, and closure

**Files:** modify `bridge/integration.py`, `bridge/landing.py`, `bridge/adapter.py`, `bridge/command.py`, `bridge/retry.py`, `tests/test_integration_lifecycle.py`, `tests/test_phase_bridge.py`.

Provide `IntegrationGuard.pre_cas(record)` and `post_cas(record)`. Pre-CAS checks the association, selected collections, integration receipt/current generation, cancellation state, original target base, candidate identity, and writes a durable P4 landing authorization. Post-CAS instead requires its matching P1 intent/receipt and a target containing that candidate; it must not require the old target base or a non-cancelled historical member. Invoke the phase-aware guard from direct landing, landing retry, recovery finishing, `PhaseAdapter.land`, and `PhaseAdapter.close`; no direct or recovery path may bypass it. P1 continues to prove gate correspondence, check policy/results, artifact ancestry, CAS, landing receipt, and final stage close.

For the final pre-CAS recheck, durable authorization, P1 intent/CAS handoff, and cancellation, use the same short canonical order: target-claim lock → owner lock → affected member bands in sorted root-ID order. Never hold it through writer/reviewer execution or repository checks. Cancellation before the handoff fences the candidate; cancellation after a proved CAS yields post-CAS recovery, never invalidation or rollback. Before CAS, target movement yields P1's unlanded branch-moved result. An explicit P4 retry atomically transfers the target claim, snapshots the new target, reserves a new integration attempt under the same original owner, and reruns ordinary writer/reviewer/ship; it never reuses approval or checks. Uncertain process/CAS evidence remains recoverable and blocks a new attempt.

**Tests:** faults across association, target claim, reservation, root, bridge bind, intent, CAS, receipt, and close prove one root/CAS/close per attempt and forward-only repair. Race cancellation at each ordered-handoff boundary; pre-CAS cancellation blocks CAS, while post-CAS cancellation repairs receipt/close. Cover stale bases, conflicting source edits, partial writer output, replay, source/integration cancellation, stale bridge root, direct adapter close, and recovery after CAS. Assert child receipts never land individually. Reconcile any P3 grouped-correction change to low-level member-lock APIs narrowly before dispatch.
