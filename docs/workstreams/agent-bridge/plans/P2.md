# P2 Implementation Plan

**Origin:** approved `docs/specs/2026-09-11-workflow-coordination.md`, roadmap P2 in `docs/workstreams/agent-bridge/roadmap.md`, and the parent's bounded planning dispatch.
**Goal:** a declared judgment boundary admits one identity-bound ordinary decision task, consumes its verified output once, and advances or replaces work within a durable finite allowance through Foreman CLI.
**Status:** approved for implementation under the owner-authorized workstream on 2026-09-11. Independent Astra low critique and scoped correction review approved the plan; parent verified P1 exit and accepted the revised conservative reservation contract.
**Stage:** `cr-bwo.4` is the single P2 stage. Legacy `cr-bwo.1`, `cr-bwo.2`, and `cr-bwo.3` are reconciliation inputs owned by the parent, not additional stages or dependencies.
**Out of scope:** parallel children/joins/cancellation APIs (P3); integration of siblings (P4); broad workflow/template rollout (P5); changed-graph replacements; executable gates; new runtime adapters; development-branch commits, merges or pushes.
**Constraints** (verbatim from approved spec):
- Keep Foreman deterministic and each instance single-head. Reuse Supervisor execution, profile adapters, canonical pins, process evidence, and Beads.
- Dispatch decisions through existing task execution rather than a second model execution lifecycle. Ordinary acceptance/rework invokes no decision model.
- Maintain a finite overall allowance across child admissions, decisions, retries and replacements.
- Exhausting decision capacity requires human attention; it never recursively requests another model decision.
- Preserve existing human ship approval by default; graphs may explicitly permit attributable model decisions where supported. No silent relaxation of existing pins.

Additional binding constraints: all new graph properties default to `None` and are null-elided; unchanged graphs retain exact `wf-canon-json/1` bytes and hashes. Existing root config signatures and authenticated gate payloads remain unchanged. No model action supplies a signer, grants itself permissions, raises caps or mutates active topology. Parent's concurrent P1 edits must be re-read before dispatch and preserved.

## Design contract

Names below are proposed interfaces, not claims that APIs already exist. Keep three cohesive additions: typed decision contracts, durable coordination operations, and Foreman decision orchestration. Envelope composition belongs beside existing input composition. Use existing Beads metadata transport and `BandLock`; no event bus, plugin registry, scheduler framework or second process runner.

### Declared permission and useful minimum

Add optional `Node.decision: DecisionPolicy | None` on ordinary work tasks. `DecisionPolicy` contains triggers (`fail_plan`, `allowance_exhausted`, `input_oversize`), `decision_task: DecisionTask`, permitted actions, and an optional declared instance-source name `replacement_input`. `DecisionTask` is a nonrecursive declaration: runner, model, instructions, verify checks, context_budget_bytes, max_wall, stale_after, max_infra_retries, max_steers and max_total_activations. It contains no Node, policy, nested task, topology or authority fields; reject unknown fields. At admission, deterministically lower it to an ordinary non-writing, worktree-isolated Node with `no_diff`, the generated request input, and ordinary success/failure terminals. Validate that generated graph with existing task/graph rules, resolve runtime settings and verifier identities, and pin the resulting one-task graph/config with the parent policy. Finite positive total capacity and wall limits are mandatory; retry/steer limits are finite nonnegative integers. Runtime settings never come from changed local config at dispatch. Execution uses existing Supervisor/profile behavior, not a second lifecycle. Its own failures cannot create decisions.

Use existing `fail_plan` as the explicit doubt/impossible-plan signal; instructions name both meanings. Intercept its settled, wrapper-graded outcome before ordinary routing/retry. This means the next scheduling action after an emitted valid outcome, not polling unfinished free text. Provenance/containment violations still override the claim. Graphs without a policy retain current behavior. Ordinary `accept`, `reject`, `fail_code` and successful transitions never invoke the decision task.

Allowed actions are `continue_declared`, `replace`, and `human`. `continue_declared` follows precisely the previously recorded deterministic route and consumes normal bounds; it cannot retry a refused mint or select a new edge. Omit it from exhausted/oversize requests. `replace` creates a fresh run of the SAME canonical graph, resolved runtime policy and verification/human-gate contract, at the request's proved artifact commit. It adds bounded advisory revision text only to the policy's declared optional instance source; retain every original essential input and requirement. Admission validates that `replacement_input` exists, has producer `instance`, is optional in the original graph, and is bound by at least one ordinary work task through `Node.inputs`. Derive and pin the nonempty consumer-name set from those bindings; reject dangling sources or consumers. When revision text is present, that source becomes runtime-essential for EVERY bound consumer: optional-at-authoring means it may be absent on the initial run, not removable from a replacement. Persist its digest and consumer set in replacement admission metadata; recovery reconstructs the same essential classification. Preflight the available required envelope before replacement dispatch; any later consumer whose complete essential envelope cannot fit refuses before its dispatch and reports human attention. Advice never appears in the budget-omission set. This is useful scoped replanning, not arbitrary graph construction. Disable replacement when admission validation fails or known required inputs cannot fit. Human attention pauses the coordination record directly and reports why; it does not fabricate or close a graph gate.

An open explicit human gate takes precedence and prevents a model boundary from being opened or consumed. Existing gate → gate refusal and the human-only backedge exemption remain unchanged; coordinated total-ceiling raises are additionally constrained by the immutable allocation below. A replacement re-executes its graph and obtains fresh human approval; predecessor approval never transfers. P2 decision-enabled phase-bridge roots may continue normally, but replacement on a bridge-managed root returns human attention until bridge replacement binding is explicitly supported: never let the bridge land the obsolete root. Standalone Foreman replacement is the P2 end-to-end proof. **P3 owns bridge replacement root binding:** use the consumed replacement receipt and current slot generation to make the bridge follow the authoritative successor root; reject landing/closure from its predecessor and test recovery between replacement admission and bridge binding. Parent updates the roadmap; P5 proves that binding through normal phase execution. P2 does not claim this integration.

### Identity, durable state and P3 interfaces

`CoordinationLink` = owner root ID, logical slot, generation, predecessor root ID (nullable), causing request ID (nullable). The original work root is the durable owner; decision and replacement roots carry the same owner. `RootMetadata.coordination` is optional. Runtime replacement lineage is separate from `RootMetadata.superseded_by`, which currently means a duplicate-create loser.

`BoundaryIdentity` = owner/root ID, root generation, canonical graph hash, config signature, source activation ID, boundary kind, intended route/mint digest, artifact commit + tree (or explicit absence), policy digest. `DecisionRequest` adds request ID (hash of canonical boundary identity), immutable allowed actions, budget snapshot, envelope reference/digest, decision-root admission key and current attempt ID. Request identities never derive from model-supplied text.

`DecisionResponse` is one strict JSON object in `WF_ARTIFACT_DIR/decision.json`, at most 16 KiB UTF-8: schema version, request ID/digest, parent generation, source artifact digest, producing root/activation IDs, action, and bounded rationale/revision text. Unknown fields/actions and duplicate JSON keys refuse. Attribution comes from Supervisor dispatch metadata, not echoed model identity. Read only the output tree recorded in successful non-writing completion evidence; check path, bytes and tree identity, never a mutable worktree file or stdout.

`CoordinationState` is a typed, finite ledger in owner-root metadata: immutable cap policy, active slot generations, whole-member reservations, requests and consumption/action intents. New metadata keys are optional; pin fields are never rewritten. Existing `metadata_dict`/client file transport persists it. Admission, reservation and consumption updates reload under a canonical owner lock derived from the real Beads workspace plus owner root ID. Lock order when both are needed is owner then instance band; never tick another root while holding the parent's band or hold the owner lock while an agent executes.

Local activation/gate/steer creation uses the existing instance band and local bounds, with no per-operation global debit or owner-lock acquisition. Existing wrapper steer continuation remains intact. Completed lifecycle evidence stays writable under its existing band. For coordinated members, before mint/dispatch validate durable reservation/linkage and current generation; immediately before launch re-read under the member band. Replacement fencing acquires that same member band under the owner scope, so launch and invalidation cannot race past one another. Direct `tick`/`supervise` cannot bypass this check. Coordinated public local mutation paths must require/reuse the canonical member band for the check-and-create section (a direct caller without it refuses); this is local serialization, not a new global accounting loop.

Durable operations in `bdio/coordination.py`, exposed through `WorkflowStore`:
- `reserve(owner_id: str, admission_key: str, capacity: MemberCapacity) -> Reservation`: reserve a whole member once; identical replay returns the same reservation, conflicting reuse refuses. `MemberCapacity` contains immutable positive activation ceiling, member kind (`work`, `decision`, `replacement`, or P3 `child`) and decision-attempt capacity (the full activation ceiling for decision members, zero otherwise). Owner totals sum reservations, not lifecycle events.
- `admit_member(owner_id: str, slot: str, generation: int, admission: MemberAdmission) -> MemberReceipt`: `MemberAdmission` carries pinned definition/config/inputs/base and `CoordinationLink`; deterministic key binds slot/generation and reservation. Persist intent before `create_root`; restart re-finds the same root and repairs receipt. No independent admission budget.
- `open_decision(boundary: BoundaryIdentity) -> DecisionRequest`: one request per boundary, same payload on replay.
- `consume_decision(request_id: str, response: DecisionResponse) -> DecisionConsumption`: under owner lock, re-read request, current root/head/artifact, policy, active attempt/generation and output evidence; persist response digest plus action intent in ONE metadata update. Return identical recorded receipt on internal recovery; reject a second external response, even identical, as already consumed.
- `reconcile_action(request_id: str) -> DecisionConsumption`: repair the saved continue/replacement/human action; never re-interpret a model response. Replacement reserves/adopts the next generation and fences the predecessor before work can dispatch. Admit only after predecessor has no live or indeterminate process, using existing evidence. A request opened at a settled boundary normally has no running work.
- `coordination_view(owner_id: str) -> CoordinationView`: authoritative active root, pending request/attempt, consumption, human-attention reason, caps/reserved capacities, separate actual usage telemetry and lineage. P3 consumes this, the admission and reservation operations, and current-generation checks; P3 adds child slots, joins and cancellation rather than another ledger.

Request states: `requested → admitted → awaiting_output → consumed → applied`, or `human_attention`/`invalidated`. An invalid output records its digest/reason and yields human attention in P2; no automatic parse-repair model loop. Ordinary decision-task infrastructure retries remain enabled within both local and shared caps. Changing attempt invalidates old attempt output. Restart resumes the saved identities; stale/cancelled/replaced outputs cannot advance a root. Consumed intent blocks normal head routing until repaired; applied continue records which head was handled so the boundary cannot reopen.

### Finite shared accounting

New `InstanceBounds.coordination_limits: CoordinationLimits | None` is required when any decision policy is enabled: positive integers `max_members`, `max_activations`, `max_decision_attempts`, `max_replacements`. No implicit unlimited values. At each admission reserve the ENTIRE finite resolved local `MAX_TOTAL_ACTIVATIONS` as immutable member ceiling H, plus one member slot. Reserve the initial root, each decision root, each replacement and each P3 child against the ORIGINAL owner limits. A decision reserves H units against BOTH global activation capacity and decision-attempt capacity; this deliberately over-reserves when gates or unused retries occupy capacity. A replacement also reserves one replacement slot. Reserve before member execution, persist admission intent, and bind the reservation ID, H and admission digest into member metadata; the initial root cannot mint until linkage and reservation are durable. Refuse insufficient capacity instead of silently reducing the member's declared maximum. Existing roots cannot enable coordination after work has begun.

Reservations are monotone and never refunded, including unused or abandoned capacity; replay reuses the same reservation. Ordinary entry/edge activations, infra retries, steer continuations, decision retries and gates consume only the existing LOCAL ceiling. They do not write the global ledger or acquire the owner lock. Report `reserved_activation_capacity` and `reserved_decision_attempt_capacity` separately from observed counts/provider telemetry; reserved capacity is not actual usage.

`member_ceiling(root: RootRecord) -> int | None` reads the validated immutable allocation (None only for legacy uncoordinated roots). In `bdio/bounds.py`, defensively clamp effective `MAX_TOTAL_ACTIVATIONS` to min(existing effective value, H), including previously persisted signed raises. In `bdio/gates.py:_assert_raises_bound`, reject a new human total-ceiling rebudget above H before closing its gate: do not accept a permission and merely clamp it afterward. Other local human raises retain their meaning, but cannot escape the total H. Existing uncoordinated roots retain their old semantics and pins.

**Necessary local exception fix:** `bdio/gates.py:200` currently exempts HALT from the ceiling predicate. With H occupied, opening a halt creates bead H+1; closing it and opening another creates H+2. Therefore reservation alone cannot bound every gate. For coordinated members, apply the immutable allocation check to ALL new gates, including HALT; retain idempotent lookup of existing gates. At H, return human-attention state/report without allocating another gate. Persist that state through the next owner-scoped Foreman reconciliation, never by acquiring the owner lock from a wrapper's band. Legacy halt behavior remains unchanged. Test this counterexample explicitly; do not assume the current predicate already enforces it.

Finite guarantee: for every member i, local serialized check/create enforces counted activations + gates <= H_i. Thus total count <= sum(H_i) <= owner's max_activations; decision attempts <= sum(H_decision) <= max_decision_attempts. Retries and steer continuations are ordinary counted activations; no retry type resets H. Reservation count and replacement-kind count are bounded by the other two owner caps. A race residue is counted, never excluded; encountering an inconsistent over-cap record fences dispatch and reports human attention rather than claiming the invariant held. The guarantee relies on the existing single-flight instance band; coordinated direct unlocked mutations must refuse, not depend on post-create duplicate reconciliation.

A local refusal can create one decision only when policy permits and capacity remains to reserve that entire decision member. Overall reservation exhaustion goes directly to durable human attention. Recheck remaining capacity when consuming a replacement action; a fresh local counter consumes a fresh full reservation, never resets the owner's totals. No in-place model rebudget. Human attention needs no new activation/gate when capacity is full. Finite member capacities plus finite task wall limits bound execution; CLI `--max-wall` remains a polling-session bound, not a fresh run allowance.

### Complete envelope and configuration semantics

Add optional `Node.context_budget_bytes: int | None`, resolved via `TASK_SETTING_TYPES` and `NodeSetting.CONTEXT_BUDGET_BYTES`. Require a positive explicit value for decision-enabled work and its decision task. Update task-field validation from mandatory `token_budget` to at least one of `token_budget` or `context_budget_bytes`; validate each supplied field as positive and permit both. Byte-only graphs must validate, resolve and admit without synthesizing the obsolete field. Legacy token-only graph bodies retain exact bytes/hash; the conditional decision-enabled admission requirement is stricter than legacy parsing. For legacy roots without the field, use an explicit 262144-byte safety ceiling, reported as `legacy_safety_default`, without changing pinned bytes/config. Old `token_budget` remains readable and pin-compatible but is deprecated, not converted to bytes or claimed as enforced: decision-enabled admission containing it must also specify `context_budget_bytes`, otherwise refuse with a migration message. Legacy graphs, including newly admitted runs without decision permission, remain usable with the explicit safety ceiling and a durable/CLI `legacy_token_budget_ignored` diagnostic. If both fields exist, bytes controls composition and reports that diagnostic; no path silently treats the old field as enforced. Update the old spec's trim-budget claim and usage examples; provider usage remains telemetry, not this limit.

`compose_envelope(...) -> ComposedEnvelope` returns exact brief text, UTF-8 byte count, limit, counting method `utf8-bytes`, included source identities and `InputOmission` records. Bound the FULL serialized brief: protocol, facts, instructions, labels/separators, mandatory request/identity frame, inputs and test clauses. No hidden append after checking; `_task_builder` uses exactly the checked text. This bounds interpreter-produced input, not vendor system prompts, tool results or generated output tokens.

Classify sources before materialization. Missing optional sources produce omissions with reason `missing`; optional sources removed for size produce `budget`, full reference/digest and measured size. Remove entire optional sources by highest `trim_priority` first (larger number = less important), ties by source name. Required inputs, present replacement advice for its bound consumers, and mandatory sections are never truncated or dropped. Classify replacement advice using immutable admission metadata before the optional-source selection pass, not the authored optional flag alone. Store the full omission manifest durably outside the prompt, bound its entries by declared sources, and include its reference/digest and a compact count in the checked envelope. Recompose/count after each omission, including manifest-pointer overhead. Bound Git blob/diff reads with size preflight or bounded streaming so refusal does not first allocate unbounded content; retain original objects by reference.

`EnvelopeRefusal` records required bytes (exact only when measured), limit, offending identities and counting method; for streaming overflow report a measured lower bound explicitly. No dispatch occurs. If policy permits, a small separately bounded request describes the refusal by references; otherwise human attention. Oversize decision essentials go directly to human attention. Do not recursively compose another decision.
