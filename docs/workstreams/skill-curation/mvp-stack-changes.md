# mvp-stack phase 1: what changed against dws-workflow

Snapshot 2026-11-01. Scope: `git diff ab4f6e1` on branch `mvp-stack` (three
commits plus uncommitted work) and the untracked files, excluding the
gitignored `scratchpad/`. Bead `cr-r2pa.1.8`. The narrative is read from the
diffs; section 4 is generated by `scratchpad/mvp-stack/change-report/facts.py`
(gitignored; see "Regenerating" at the end).

## 1. Summary

- **Every task now starts at a router.** `AGENTS.md` tells the agent to invoke
  `mvp-mode` first; it picks a playbook, the principles whose situation holds
  and the narrowest skill. `skill-router` is retired to a manual pointer.
- **A bug fix is a playbook, not a skill.** The new `bug-fix` playbook runs the
  gates (confirmed cause before any production change, proof, rerun, attempt
  log, two-failure stop, closeout); `systematic-debugging` now only diagnoses
  and changes no production code.
- **Fourteen principles** (judgement lenses from pstack, rewritten) are
  available, router-only, each with a one-line situation.
- **Delegation and verification policy changed.** At top level the agent
  hands independent work to subagents by default (router rule); a delegate
  delegates further only when its brief allows it. Existing tools and checks
  come first; a rerunnable tool is built only when it saves repeated work or
  supplies missing proof (`build-a-lever`); recurring lessons that code can
  decide become checks; results are verified on the real artifact.
- **The registry understands playbooks**: step lists in playbook frontmatter,
  a generated `harness_lifecycle/registry/STEPS.md`, playbooks as trait holders, and `registry steps diff`.

## 2. By area

### AGENTS.md

Four edits; behaviour change after each.

1. Learnings (Context section).
   - Before: "Record verified, likely-to-recur patterns in
     `.repo-context/learnings.md`; write other persistent memory only when
     requested."
   - After: "A verified, likely-to-recur lesson that code can decide becomes a
     check (lint, flag, runtime check or script); record others in
     `.repo-context/learnings.md`. Write other persistent memory only when
     requested."
   - Change: a decidable lesson is enforced by code instead of written down.
2. Delegation (Implementation and effort). One line replaced by two.
   - Before: "Delegate bounded independent work when it materially improves
     speed, context use, or review quality within budget and runtime limits;
     keep small work local."
   - After: "Use existing deterministic tools and checks where they suffice.
     Build a rerunnable tool when it materially reduces repeated work or
     supplies proof a reviewer needs, and keep its output. When one
     deterministic pass can process every unit, run a script rather than
     fanning the units out to delegates." and "Inside a delegated task,
     delegate further only when your brief allows it; at top level, `mvp-mode`
     sets when to delegate. Keep small work local."
   - Change: a tool when it pays (the build-the-lever ruling R10, revised
     2026-11-01 after review); the delegation threshold moves out of
     `AGENTS.md` (which delegates also load) into the router as "delegate
     independent work by default" for the top-level agent only (amended
     ruling R15, a recorded owner override of prompting-guide rule C-14).
3. Verification.
   - Before: "Inspect the final diff and Git status. Report outcomes, actual
     checks, and limitations; distinguish pre-existing failures from
     regressions."
   - After: "Verify results by observing the real artifact, never a proxy, a
     cached view, or a self-report. Inspect the final diff and Git status. …"
     (rest unchanged).
   - Change: a self-report or cached view no longer counts as verification.
4. New session (added).
   - Before: none.
   - After: "At the start of every task, invoke the `mvp-mode` skill: it
     routes the task to a playbook, principle or skill."
   - Change: the router is sticky on every vendor and survives compaction
     (unit-kinds R5, R7).

### Router: `mvp-mode` replaces `skill-router`

- **Before:** `.claude/skills/skill-router/SKILL.md` was an optional,
  model-invocable router: a ten-row need → skill table plus a generated
  catalog of all skills and slash commands, in one file.
- **After:** `.claude/skills/mvp-mode/SKILL.md` (model-invocable, always
  invoked via `AGENTS.md`) holds one line per kind, the pick rules, the
  delegation default for the top-level agent, the rule that a delegate never
  starts a playbook, the shared rules for running a playbook (steps copied to
  the todo list, skipped steps kept as `skip: <reason>`, callees run whole,
  closeout on every exit), one line per playbook, one line per principle and
  an eight-row skills-by-situation table. The full generated catalog moved to
  `.claude/skills/mvp-mode/references/catalog.md`, read only when unsure or
  asked what exists.
- **`skill-router`:** now `disable-model-invocation: true` (Codex sidecar
  `allow_implicit_invocation: false`) with a three-line pointer to `mvp-mode`.
  Kept, not deleted, because the registry views match exact skill names
  (deviation log, R1).
- **`.claude/scripts/skill-catalog.py`:** retargeted from `skill-router` to
  `mvp-mode`'s catalog, and now also lints the router: every installed
  `principle-*` skill and playbook file needs a `target`: situation entry,
  every entry must name something installed, bare skill names must resolve,
  and the router must point at its catalog (comments and fenced examples
  ignored).
- **Behaviour change:** routing is mandatory at task start instead of
  optional; the always-loaded part is lean and the catalog is loaded on
  demand; a unit the router cannot reach fails the catalog check.

### Playbooks: `bug-fix`

- **Before:** no playbooks. `systematic-debugging` both diagnosed and fixed,
  and held hardening and timing-flake fix material.
- **After:** `.claude/skills/mvp-mode/playbooks/bug-fix.md`, seven steps with
  a machine-read frontmatter step list: (1) obvious-cause skip, only for a
  deterministic failing command whose output points at the cause; (2)
  diagnose via `systematic-debugging`; (3) fix with proof, using the failing
  check or `test-driven-development` test-first, and fix other in-scope
  instances; (4) rerun the original scenario; (5) attempt log, revert failed
  attempts, stop after two failed fixes; (6) harden only when the defect
  reveals another boundary problem; (7) closeout on every exit. A reply
  contract names five exits (fixed, changed with verification incomplete,
  stopped provisional, stopped unresolved, stopped at step 5).
- **References moved in:** `.claude/skills/mvp-mode/playbooks/bug-fix/hardening.md`
  (renamed from `.claude/skills/systematic-debugging/references/post-fix-hardening.md`, with
  the repo-specific pydantic sentence generalised) and
  `.claude/skills/mvp-mode/playbooks/bug-fix/timing-flakes.md` (the
  condition-based-waiting section cut from
  `.claude/skills/systematic-debugging/references/non-reproducible-bugs.md`).
- **Behaviour change:** production code changes only for a confirmed cause;
  a symptom-hiding change (retry, longer timeout, skipped test) is named as
  not a fix; "fixed" requires the original scenario to pass its rerun.
  Deviation logged (B3): in the S8 trial `test-driven-development` was called
  in one of three fix runs.

### Principles (14 new units)

Each is `.claude/skills/principle-<name>/SKILL.md` with
`disable-model-invocation: true` and a Codex sidecar that disallows implicit
invocation: reached only through the router (P7), invocable by slash name.

| Principle | Situation (router line) | Core line |
|---|---|---|
| `principle-attack-the-premise` | two or more fixes resting on one belief have failed the same gate | Name and test the shared belief instead of building another fix on it. |
| `principle-boundary-discipline` | wiring validation, error handling or a framework adapter | Check data where it enters the system and trust it after that. |
| `principle-experience-first` | a product, UX or feature-scope tradeoff | The work is judged by whoever consumes it; explain impact from their side. |
| `principle-explain-the-number` | before measuring, or before trusting, reporting or acting on a measured number | A number is evidence only once you know what produced it. |
| `principle-make-operations-idempotent` | a command, lifecycle step or loop that may crash, restart or retry | A state-changing operation converges on the same end state however often it runs. |
| `principle-migrate-without-shims` | replacing an internal API with no external users, or a planned migration with phase boundaries | Converge on the target design instead of carrying compatibility code. |
| `principle-minimize-reader-load` | reviewing or shaping code that is hard to trace | Judge maintainability by the layers and state a reader must hold, not line counts. |
| `principle-model-the-domain` | stateful logic, a growing if/else chain, or a repeated shape assumption | Choose the structure before the logic; the right structure removes logic. |
| `principle-redesign-from-first-principles` | integrating a new requirement into an existing design | Design as if the requirement had been there from the start. |
| `principle-separate-before-serializing-shared-state` | concurrent actors in designed code or tooling may write the same file, branch, key or object | Remove the shared write before coordinating it (code and tooling only). |
| `principle-sequence-verifiable-units` | multi-step work or stacking commits | Every step ends somewhere a check can confirm; record baseline results first. |
| `principle-subtract-before-you-add` | sequencing an addition, refactor or rewrite | Remove the dead code the change touches before adding; report other removals. |
| `principle-test-behavior-not-implementation` | writing, changing or keeping any test | A test must fail when behaviour breaks and survive internal restructuring. |
| `principle-type-system-discipline` | designing types or a signature in a typed language | Let the checker reject impossible states instead of testing them at runtime. |

Ten pstack principles got no unit: their rows were rejected, deferred,
covered by existing units, or became `AGENTS.md` lines or the new skill
`build-a-lever` (rulings in the sealed reports below).

### Skills

- **New: `build-a-lever`** (`.claude/skills/build-a-lever/SKILL.md`,
  model-invocable). One unit by hand, the smallest tool, rerun-safe, prove the
  tool against the hand unit, then run it on the rest; propose committing the
  tool only when the work will be rerun or audited.
- **New: `mvp-mode`** (router, above).
- **Changed: `systematic-debugging`.** Description and body now deliver a
  diagnosis only, with three statuses (confirmed, provisional, unresolved)
  and no production change beyond temporary instrumentation. Added: suspect
  the check or probe before the system, take a prior attempt log as
  evidence, tag every probe with one prefix, keep asking why until the cause
  is a wrong decision, and decide whether the triggering state is legitimate
  before blaming where the symptom surfaced; a failure that appears only
  after a restart points first at persisted state. Removed (moved to `bug-fix`):
  fix, regression proof, attempt log, two-failure stop, hardening.
  `.claude/skills/systematic-debugging/references/localization.md` drops the old phase numbers, reports the
  origin as the cause instead of fixing there;
  `.claude/skills/systematic-debugging/references/non-reproducible-bugs.md`
  loses the timing-flake fix section.
- **Changed: `execution`.** Step 2 now says how to handle an unclear failure
  inside a task: use `systematic-debugging`, fix only a confirmed cause, prove
  it, rerun, log attempts, stop after two failed fixes; route a top-level bug
  fix to `mvp-mode`, or report the route to the parent when delegated.
- **Changed: `performance-optimization`.** A regression whose cause is the
  question is a bug: route to the bug-fix playbook (via `mvp-mode`, or report
  to the parent); diagnosis alone uses `systematic-debugging`.
- **Changed: `prototype`.** New competing-variants branch (ruling R12): for an
  unprecedented interaction or architecture, or a feel-dependent product
  decision, build two or three runnable variants and compare them; the
  description gained that trigger and `.claude/skills/prototype/UI.md` points to the branch.
- **Changed: `authoring-for-agents`.** Once a check enforces a rule, replace
  the restating instruction with a pointer to the check; a recurring
  judgement lesson revises the implicated instruction and adds one failure
  example instead of repeating the rule.
- **Retired: `skill-router`** (manual pointer, above).
